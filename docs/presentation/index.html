ROBOFACTORY / PROJECT OVERVIEW

ReloBot Platform Architecture

A distributed micro-ROS and containerized ROS 2 system with an onboard AI agent running on Raspberry Pi 5.

Design Philosophy
Commercial robotic platforms are closed black boxes with high cloud latency. We built a hardware-first, distributed architecture with sub-millisecond control loops and complete local autonomy.
Core System Specifications
REV-C 2026
  • Real-Time MCUs 4x dedicated RP2040 micro-ROS agents over isolated USB CDC channels
  • Central Compute Raspberry Pi 5 (8GB RAM), PCIe NVMe, multi-container Docker runtime
  • State & SLAM 9-DOF IMU + 60 CPR optical encoders fused via EKF; 360° 2D LiDAR costmaps
  • Autonomous Agent On-device Google Antigravity (AGY) core with local Piper neural TTS
Key Engineering Tenets
  • Physical loop isolation: Real-time motor PWM & watchdogs survive high-level container restarts.
  • Zero cloud reliance: Telemetry, path planning, vision, and voice synthesis run 100% on the machine.

SOFTWARE ARCHITECTURE / DIGITAL TWIN

Containerized ROS 2 & Gazebo Simulation

Zero host pollution with shared-memory IPC, paired with 100% API parity in the virtual digital twin.

Why Docker on Host?
Robotics stacks are notoriously brittle with OS dependencies. Containerizing every service ensures reproducible builds, while host-mode IPC preserves microsecond transport speeds.
Multi-Container Orchestration Architecture
HOST RUNTIME
  • Host Purity: Host OS only runs Docker and serial device mounts. No ROS dependencies installed on host.
  • Zero Latency Transport: network_mode: host and ipc: host enable FastDDS shared memory communication.
  • Volume Hot-Reloading: Code in ros2_ws/src/ is mounted directly; rebuilds and web changes take effect immediately.
  • Standard ROS 2 Interfaces: Uses topic_based_ros2_control, robot_localization EKF, and standard Nav2 behavior trees.
ros2_nav2 · ros2_voice_chat · ros2_rosbridge · ros2_frontend
Zero-Risk Gazebo Digital Twin
SIMULATION
  • 100% API Parity: Identical topic names (/cmd_vel, /scan), TF frame hierarchy (map → odom → base_link), and action servers.
  • Physics & Friction Models: garden.sdf includes real lawn friction parameters, perimeter obstacles, and rough terrain.
  • Emulated Sensors: Simulated 360° laser scans, synthetic camera feeds, and blade motor speed feedbacks.
  • Instant Launch Command: ./start_sim.sh up --gui --dev tests the entire autonomy pipeline on a laptop.
Saved ~3 weeks of bench testing before running physical blades.

ON-DEVICE AI / AGENT PLATFORM

The Self-Aware Robot: AGY Core

Natural language chat is just the operator interface — AGY is an extensible on-device agent platform.

Why Run Locally on Pi 5?
Robots lose Wi-Fi in the yard all the time. Critical diagnostics, sensor reasoning, and spoken operator feedback must function autonomously without waiting for a cloud round-trip.
RoboFactory AGY Agent Platform
AGY RUNTIME
  • Onboard Runtime: Google Antigravity & AGY agent executed inside the ros2_voice_chat container.
  • Full Introspection: Direct programmatic access to FastDDS telemetry, ROS 2 parameters, topic streams, and container logs.
  • Beyond Chat: Natural language is just the operator UI; AGY's primary role is proactive system oversight and automated fault detection.
  • Extensible Hooks: Evolving toward automated node restarts, PID parameter tuning, and multi-robot swarm task allocation.
Piper Neural Voice Pipeline
LOCAL TTS
  • Sub-100ms Latency: Local neural speech synthesis running purely on Raspberry Pi 5 CPU cores with zero cloud dependencies.
  • Pipelined Token Streaming: Regex punctuation chunking allows audio playback to start while the LLM is still generating tokens.
  • Concurrent Audio Out: Simultaneous broadcast to physical robot chassis speaker and operator browser Web Audio.
  • Engineering Persona: Tuned for concise, razor-sharp technical diagnostics and status reports.
Regex chunking cut voice delay from 3.2s down to 240ms.

FIELD ENGINEERING / LESSONS LEARNED

Hard Problems Solved in Hardware & Software

Concrete engineering hurdles and battle-tested solutions from field deployment.

Field Reliability
Robotics is the art of fighting real-world physics. Theory guarantees nothing until hardware survives the elements and edge-case network loads.
FastDDS UDP Buffer Storm
KERNEL SYSCTL
Problem: Linux default 212 KB UDP socket buffer choked under high-frequency SLAM map exchanges. Cascading retransmissions caused 100% CPU lockup.
Fix: net.core.rmem_max = 67108864 (64 MB socket buffer) in /etc/sysctl.d/99-ros2-fastdds.conf.
Wheel Velocity & Stiction Calibration
MICRO-ROS REGRESSION
Problem: DC gearmotors exhibit non-linear friction deadbands; left and right motors had different starting torque thresholds.
Fix: Automated velocity sweep ($PWM = k \cdot v + b$) in helpers/wheel_calibration embedded into firmware.
5 GHz Wi-Fi Region Lockdown on Pi 5
HOST WIRELESS
Problem: Raspberry Pi 5 kernel defaulted to country 99 (DFS-UNSET), disabling 5 GHz bands and throttling camera stream.
Fix: Configured persistent regulatory domain unlocking Channel 52 for low-latency RTSP camera streams.
AI Agent Context & Reasoning Latency
SESSION LIFECYCLE
Problem: Expired chat session IDs crashed CLI; raw <think> tokens introduced 10–20s delays before speech playback.
Fix: Dynamic session renewal, reasoning token suppression (<50ms TTFT), and RAM model pre-warming.
Field Hardening: 64MB FastDDS Buffers · Firmware Stiction PI · 5 GHz Wi-Fi Unlock · <50ms TTFT Voice
Every fix was paid for with a late-night debugging session.
